# 人間の自動同期とサイドバーのテスト

- [x] 人間の自動確認・変更通知による同期は前回完了から1時間空け、通知を集約する
- [x] 初回ON・Root変更・手動同期は待機せず、自動更新OFF・機能OFFでは自動取得しない
- [x] 1時間境界・変更なしスキップ・失敗後の再試行・保存先切替を短い試験用間隔で実ワーカー検証する
- [x] 同期中に届いた通知を次回へ保持し、自動更新OFFへの変更で古い予約を解除する
- [x] 同期状況・エラー・診断・手動再同期を左メニューの人間セクション末尾へ移す
- [x] 狭い高さ、長いエラー、ライト/ダークでも同期ボタンと設定が操作できる
- [x] AIの自動更新間隔とReiのデータ・設定は変更しない
- [x] 全回帰・静的検査・ビルド・Windowsネイティブ・画面確認

運用終了条件: PR CI、通常マージ、マージ後CI、main更新、専用worktreeとローカル/リモートブランチの通常削除。

ローカル検証: Rust135（全target/benchmark feature/直列）、Vitest117、Python17、release9、Windows native19（最終全体18成功＋既存起動試験のDevTools接続タイムアウト1件を単独再確認して成功）、計297ケースを確認。fmt/Clippy/typecheck/lint/Prettier/Vite/Tauri NSIS成功。既存5秒待機がローカル並列でタイムアウトしたため、待機を延長せず直列で全件を確認した。CIでは既定の並列実行とネイティブ全19件も確認する。

合成worker smoke（1万件、明示的なbenchmark featureの1秒間隔）も成功。製品の1時間境界は通常constructorと時計境界の試験で検証し、通知なしの再試行・保存先切替はprivate constructorの短い試験間隔で検証した。Reiの原本や設定は変更していない。

画面例は合成データのみ: [日](screenshots/human-bands-day.png) / [週](screenshots/human-bands-week.png)。600px高と長い読取エラーでも、再同期・設定ボタンが操作できることをネイティブ確認した。

キャッシュの禁止内容検査は、手動同期の完了をrevisionで待ち、Windowsの一時的なEBUSY/ファイル消滅だけを再試行してから内容を検査する。禁止内容を含む場合の失敗を再試行で隠さない。
