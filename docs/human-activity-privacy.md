# 人間アクティビティのプライバシー境界

目的は「いつ、どの種別の活動が観測されたか」の表示であり、具体的内容の監視・評価・再分類は行わない。
バックエンド・設定・期間取得・削除と、日週/月の表示・詳細・集計に共通する境界を記録する。

| 境界                           | 許可する情報と保護                                                                                                                            |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Rei SQLite 内                  | activity_records のJSONを内部で検証・抽出。元のDBをread-only/query_onlyで開き、書込・移行・checkpoint・VACUUM・原本コピーをしない             |
| Rust へ渡す値                  | ID（最大256byte）、開始ms、整数の推定秒、SQLite内で3種別へ正規化した値、有限のエラーコード。元JSON・元判定・活動の具体的内容を取得しない      |
| 一時DB / TEMP差分              | 許可フィールドとそのハッシュのみ。256行ずつ処理し、ソート・差分の蓄積はディスクへ置く                                                         |
| CodeCal キャッシュ             | 専用2テーブル。開始・推定継続時間・実効終了・種別・同期ID・ソース管理情報・許可フィールドだけのSHA-256                                        |
| 応答モデル                     | 記録はstart/end/kind、月要約は日付・実際の日長・種別と選択合計・観測有無、診断は固定コード/件数だけ。同期ID・ソース・元判定・パスは応答しない |
| ログ / エラー                  | 元のSQLite例外・値・パスを連結せず、固定コードだけを返す。本番モジュールにログ出力を追加しない                                                |
| AI snapshot / 既存エクスポート | 人間の観測を turns/projects/events に入れず、AI snapshotへ暗黙に追加しない                                                                    |
| CodeCal管理コピー              | 新規の移行前バックアップとLocal移行コピーから人間用2テーブルの行を除外してVACUUM。コピー元・既存バックアップは変更しない                      |
| 外部通信                       | このモジュールはSQLiteとローカルファイルだけを使い、LLM・ネットワーク・テレメトリーへ送信しない                                               |

取得しない情報には、ウィンドウ/ページタイトル、アプリ/プロセス/コマンド、ファイル名・パス・URL、画像・OCR・本文・説明・理由・推論・プロジェクト推定・入力文字列が含まれる。
ソースパスは設定・同期管理だけに使用し、人間の詳細や診断へ出さない。
不正JSON・1MiB超のpayload・型不一致をSQLのCASEで判定し、未知の判定文字列は保存しない。
巨大な値は `octet_length()` でバイト長を調べてから解析する。負数・overflow・日時範囲外は値を出さず件数診断し、既存の正常キャッシュを保持する。
活動種別の「不明」は観測済みの未確定分類であり、未観測の空白を埋めない。

## 検証

すべて合成フィクスチャを使用する。実際の個人アクティビティは利用しない。

- 私有stagingファイルの実バイトに原本の機密文字列・私的フィールドがないことを単体テストする。
- 隔離した子プロセスで取り込みを行い、応答・診断と stdout/stderr に識別可能な合成機密文字列が混入しないことを確認する。
- CodeCal DB / WAL / SHM に原本の機密文字列がないこと、原本DB/WALの実バイトが読み取りで変わらないことを確認する。
- 禁止フィールド・未知判定文字列だけを変えてもハッシュが変わらないことを確認する。
- 意図的にSQLiteのキャッシュ書込エラーを発生させ、例外の合成機密文字列がエラーやログへ出ず、前回正常値を保持することを確認する。
- AI snapshotの独立性、管理コピーの人間キャッシュ除外、コピー元とAI設定の保持を確認する。

Phase 2では設定保存失敗・OFF・ソース置換・キャッシュ再利用・旧ジョブによる削除後の復活防止・削除失敗rollback・管理一時領域のソース別回収とリンク越境拒否を試験する。
画面の期間フックは別期間・別設定・OFF後の古い応答と古い設定世代のイベントを棄却し、エラーの未知文字列も固定コードに変換する。同期ID・ソースID・原判定はフロントエンドの人間レコード型に存在しない。
ネイティブ統合試験では実IPCの3フィールド、WAL更新、OFFの拒否、再起動、確認付き削除、再ON再取り込み、AI snapshot独立性、合成秘密文字列のUI/DB/WAL/SHM非混入と管理バックアップの空キャッシュを検査する。
カレンダーブロック・0秒点・詳細・月の種別バー・種別フィルタ・明暗テーマ・小さい画面・キーボード操作をネイティブで検証する。外部リクエストは専用WebViewの人間機能ON/同期/表示経路で記録し、実行時の対象と未計測範囲を性能文書へ残す。
最大RSSと長時間WAL保持は性能試験で別に測る。OS・利用者・他アプリが作ったコピー、ディスクやファイルシステムの残存の完全消去は保証しない。

## 初回一括適用と障害時の表示

初回一括適用でアプリDBへ接続するのは、SQL投影後に許可項目だけで新規生成した私有一時DBです。非公開のHumanStageからだけ接続し、URIのmode=roとSQLiteのreadonly判定を検証します。原本DBをATTACHするAPIはありません。一時DBにpayload列がないこと、禁止値がないこと、書き込みが失敗すること、スコープ終了で接続が外れることを自動検証します。途中失敗はキャッシュtransactionをrollbackします。

現在パスにディレクトリなど識別不能なオブジェクトがある場合は固定エラーを返し、旧ソースの履歴を表示しません。月要約の取得エラー時も前回のバーを消し、再試行中の古い応答で復活させません。正常キャッシュ本体は失敗を理由に消しません。

メモリやSQLiteの自由ページを含む論理削除は、SSDの完全消去やOS・第三者バックアップの削除を保証しません。CodeCalが管理するバックアップとLocal移行コピーは人間テーブルを除外します。ユーザーが直接コピーしたDBや外部バックアップの管理は対象外です。

複合主キーにより観測IDが重複できる未知スキーマは読み取り前に拒否する。正規化stagingの一意性を原本IDの単独主キーで保証し、未知構造を推測して取り込まない。URI接続のテストには空白・日本語・%・#、Unixでは文字としてのバックスラッシュを含め、原本パスの解釈や接続先が変わらないことを検証する。
