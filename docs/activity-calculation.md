# 稼働時間の算出

## 確定区間

単位はセッションではなくターンです。task_started (または互換turn_started) のタイムスタンプを開始、同一session_id + turn_idのtask_complete / turn_aborted / task_failed等を終了にします。内部時刻はUTC Unixミリ秒です。外側のRFC3339イベント時刻を優先し、payloadのduration_msで不足を補いません。

ツール呼び出し間隔やログの無通信時間は、作業停止の根拠にしません。長いツール実行は開始と終了の間の確定区間に含まれます。終了が開始より前なら終了を採用せず、未確定のままにします。終了イベントのみから開始を推測しません。

## 状態

| 状態               | 判定                                                   | 時間集計       |
| ------------------ | ------------------------------------------------------ | -------------- |
| completed / 完了   | 明示的完了イベント                                     | 対象           |
| failed / 失敗      | 明示的ターン失敗イベント                               | 対象           |
| interrupted / 中断 | 明示的中断イベント                                     | 対象           |
| unknown / 終了不明 | 開始あり、対応する終了なし                             | 対象外         |
| running / 実行中   | UIモデルは対応、ログだけで現在性を証明できず設定しない | 未確定は対象外 |

未知終了は開始位置に破線マーカーを表示します。その高さはUIの選択領域であり、推定稼働時間ではありません。過去の開始を無条件に現在まで延長しません。短い確定区間の表示も最小2pxですが、集計は実ミリ秒を使います。

## 並列実行

半開区間 `[start,end)` を使用します。延べ稼働時間は `Σ(end-start)`。実稼働時間帯は開始順にソートし、重複・接触する区間を統合して長さを合計します。たとえば10–12時と11–13時は延べ4時間、実3時間です。プロジェクト別は各プロジェクトの延べ時間です。

UIの表示期間とフィルタに合わせて再計算します。並列ブロックは重なりがつながるグループごとにレーンへ配置し、最も多い同時レーン数で横幅を分配します。ブロックを隠して重ねません。短いブロックの全内容はキーボードフォーカスとクリックで参照できます。

## 日付境界・タイムゾーン

日次分割では各区間を指定IANAタイムゾーンへ変換し、翌ローカル日の開始でクリップして繰り返します。日付境界をUTCに戻して差を取るため、日を24時間固定で計算しません。Asia/Tokyoの23–翌02時は1時間と2時間へ分割。America/New_Yorkの2026-03-08は23時間、2026-11-01は25時間です。テストで両方を検証しています。

日付境界の午前0時が存在しないゾーンは、直後の有効な時刻を探します（最大3時間）。暦日が丸ごと消える歴史的なタイムゾーン変更には現在対応していません。通常の夏時間変更は対象です。

週の通常列は0–24時、夏時間変更列はその日の実長を同じ高さに写像し、列内にUTCオフセット付きの独立した時刻目盛りを出します。詳細には正確な時刻・ゾーンを表示します。

## ヒートマップ

既定は重複を除いた時間、切り替えで延べ時間です。5段階は0、0より大きく1時間未満、1–3時間、3–6時間、6時間以上。しきい値の1/3/6は設定できます。同じ時間には月をまたいでも同じ濃さを割り当てます。未確定ターンはターン数に含み、色の時間には加えません。
