# テストと検証

## 自動テスト

| 種類              | 範囲                                                                                                                                                                                                                                       |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Rust integration  | JSONL、未知/不正行、UTF-8、ターン対応付け、メタデータ・cwd、SQLite再起動、並列区間、日付跨ぎ・DST、追記断片、切り詰め、重複アーカイブ、リネーム、同サイズ置換、対象範囲、未来スキーマ拒否、Local保存・RoamingからのWAL付き移行・上書き防止 |
| Vitest / RTL      | 週/月の表示、移動、絞り込み、詳細とソース参照、日選択、テーマ保存、空・読み込み・エラー・診断、計算とレーン                                                                                                                                |
| Playwright native | 合成ログ取り込み→プロジェクト認識→週→詳細/トークン/生ログ→月/日詳細→週→追記自動反映→再起動とSQLite保持                                                                                                                                     |

Windowsの実行ファイルをビルドしてから npm run test:e2e を実行します。通常のブラウザーをモックしたE2Eではありません。WebView2のローカルCDPポート9223へPlaywrightが接続し、Rust IPCとSQLiteを含めて検証します。テスト時だけWebView2の追加起動引数を渡します。製品からリモートデバッグは有効化しません。

E2Eは .local/native-時刻/ にログとデータを隔離します。再起動時も同じCODECAL_DATA_DIRを使い、毎回別の空データディレクトリから始めます。スクリーンショットは合成ログだけを使用します。終了時にテスト起動したプロセスを停止します。

## 実ログと性能

2026-11-21にローカルの189ファイル・約403MBを読み取り専用で検証し、15プロジェクト・2,328ターン、11日分の集計を取得。初回処理は約16.6秒（この端末、デバッグビルド、SQLite新規）。観測時の状態は完了2,320、中断7、終了不明1でした。現在の作業ログも追記され続けるため、以後の件数・バイト数は変わります。値の入ったログはリポジトリに保存していません。

合成ログの未変更再同期は、新規JSONL行の取り込み0バイトをテストしています。ファイル識別用の先頭部分の読み取りは別途発生します。実ログの直後の再同期では実行中のログへ追記があったため約14KBを読みました。この結果を未変更0バイトの実証とはみなしません。

## 検証の限界

Windows 11 x64で実行ファイルの起動とネイティブE2E、NSISパッケージ生成を確認します。インストーラーを別のクリーンな端末に入れる検証、コード署名、Linux/macOSパッケージ、GitHubホスト上のCI実行は対象外・未検証です。ローカルの最終結果は delivery-report.md に記録します。

## カレンダービューの改善検証

ビュー切り替え時は二段階のrequestAnimationFrameでスピナーが描画されるフレームを確保し、Reactのtransitionの完了までaria-busyを維持します。RTLで両フレームの前後の状態を検証し、ネイティブE2Eでもbusy属性の遷移を観測します。

日表示の日送り・選択月の日詳細から日表示への移動を検証します。月表示の向きは実WebViewでセルの座標を取得し、隣の日が同じ行の右側、7日後が次の行の同じ列に来ることを検証します。CSSの文字列だけのテストではありません。

日別インデックスは履歴・絞り込み・タイムゾーンが変わった場合に再構築し、ビューの移動では再利用します。日をまたぐターン数の重複除去、並列区間とDSTの計算が維持されることもテストします。

共有ビルドキャッシュを使うworktreeでは、ネイティブE2Eに CODECAL_E2E_EXE で実行ファイルの絶対パスを渡せます。通常の開発・CIでは指定不要です。

## 日次タイムラインのズーム

Ctrl＋ホイールだけを非passiveのネイティブリスナーで受け取り、WebView全体のページズームを抑止します。倍率を50〜400%に制限し、マウス位置のタイムライン座標を変換して、描画後のlayout effectでスクロール位置を合わせます。時刻目盛り、背景の時刻線、作業ブロック、現在時刻線も同じ倍率で配置します。終了不明マーカーの最小選択領域は固定します。

単体・RTLでは座標保持、倍率上下限、wheelのpixel/line/page単位、リセット、通常スクロール、週表示の倍率が変わらないことを確認しています。ネイティブE2Eでは実際のCtrlキーとmouse.wheelを送り、作業ブロックの拡大、マウス位置の時刻保持（基準座標で1px未満の差）、window.innerWidthとdevicePixelRatioの不変、通常スクロールとリセットを検証しています。合成ログの画面はscreenshots/day-zoom.pngです。

## 作業ブロックのまとめ表示

グループ計算は重複、5分以内の空白、別プロジェクト、日付境界、終了不明、DST、入力順序、ターン単位への切り替えをテストしています。RTLでは既定のまとめ表示、集計の不変、個別ターンへの移動と一覧への復帰を検証します。

実Windows E2Eでは合成ログの3ターン（完了・失敗・中断）を取り込み、実55分・延べ70分・表示範囲60分になることを検証。ターン単位に切り替えた際の3ブロックと月次集計も確認します。screenshots/day-grouped.png と activity-group-details.png は合成ログです。

2026-11-21の実ログ確認では、同日の793ターンの表示が33ブロックに減り、切り替え前後でサマリーが一致しました。実ログの本文や画面はリポジトリに転記していません。件数は進行中の開発により変動します。

## ウィンドウ状態のネイティブ再起動テスト

window-state.spec.tsは、状態ファイルに位置・サイズを設定して起動し、復元を実WebViewで確認します。起動中に合成状態ファイルを削除してからネイティブウィンドウを通常終了し、ファイルの再作成とネイティブ外枠座標・サイズの記録を検証。再起動して同じ状態になることと、最大化して保存された状態の再復元も確認します。

WindowsのWebView screenX/Yは外枠の透明なリサイズ境界を含まないため、ネイティブ位置はプラグインの保存値、画面上の位置は再起動前後のWebView座標同士を比較します。ブラウザー内部座標をそのままネイティブ外枠座標と比較しません。

別シナリオで、状態ファイルなし・不正JSON・切断済みモニター相当の画面外座標からも表示できることを確認します。CODECAL_DATA_DIRとWEBVIEW2_USER_DATA_FOLDERの両方を隔離し、通常プロファイルには触れません。保存テストではtaskkillを使わず、テストで起動したプロセスのメインウィンドウを通常終了します（失敗時の後片付けのみ強制終了）。
