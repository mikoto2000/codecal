# Phase 5 テストリスト

添付実装依頼を優先する。合成データだけを使い、障害・性能上の失敗を確認してから修正する。Reiのコード・DB・設定・サービスは変更しない。

- [ ] 現在パスに識別不能な別オブジェクトがある場合、旧ソースの履歴を表示せず、旧キャッシュは保持する
- [ ] 集計取得失敗後に前回の月バーが残らず、再試行中や古い応答で復活しない
- [ ] 全禁止フィールド・未知判定・異常入力の機密文字列がDB/一時領域/IPC/UI/診断/ログ/既存export/管理backupへ混入しない
- [ ] 人間機能ON/同期/表示/詳細で外部サービスへの送信が発生しない
- [ ] 1万/10万/100万件、連番とUUID相当のID分布、通常payloadによる改善前計測
- [ ] 初回/変更なし/1件追加/1件更新/AIのみ更新の反復値、中央値・実測p95と再現条件
- [ ] 未達経路のボトルネックを改善し、Phase 0の性能予算を満たす（予算を都合よく緩和しない）
- [ ] worker経由の強制/自動/変更なし確認、多重起動防止、同期中追加更新の追従
- [ ] 巨大payload負荷・取消し・30秒期限・失敗後の正常キャッシュ保持と再試行
- [ ] 日/週/月取得の時間とIPCサイズ、密度上限の明示、長い区間と空の末尾期間
- [ ] 同期の最大メモリ使用量、Windows nativeで同期中UI応答・期間変更の動作
- [ ] 原本への継続同時writerのp95、WAL保持量と読み取り終了後の回収
- [ ] DB容量、計測回数、ハードウェア/バージョン、cold/warmの意味・未検証の明記
- [ ] Windowsの起動/設定/ソース交換/再起動/削除/テーマ/最小画面/キーボードの最終確認
- [ ] Rust/Vitest/SQLプローブ/release/native全回帰・型/lint/format/fmt/Clippy・Vite/Tauriビルド
- [ ] README、rei-history、database-schema、architecture、人間設計、プライバシー、性能結果を更新
- [ ] 既知の物理ファイル識別・SQLite安全消去・原本全走査の制約を具体的に記録
- [ ] 自己レビュー・妥当な指摘の修正・PR/CI/通常マージ/マージ後CI/main更新/専用worktreeとbranch削除
- [ ] 全Phase実績・最終検証・残課題・Git状態を報告し、元の未追跡設計書を保持する

期間取得やUIの数値は実際の経路を計測し、SQLite投影だけの値を全同期の成功根拠にしない。
